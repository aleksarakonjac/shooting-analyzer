# Shooting Analyzer Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed Serbian-language web app where approved users log in, import SIUS, SCATT and heart-rate files into one aligned training record, and review it on shooter and coach dashboards.

**Architecture:** Next.js App Router frontend on Vercel; Supabase Postgres (with row-level security), Auth and Storage. All file parsing and alignment is pure TypeScript in `src/lib`, runs in the browser at import time, and is unit-tested against the real sample files; only parsed results and the raw files are sent to Supabase. Roles and sharing are enforced by RLS, tested in SQL.

**Tech Stack:** Next.js (App Router, TypeScript), Supabase (Postgres, Auth, Storage, CLI for local dev and migrations), Vitest, sql.js (SCATT SQLite in the browser), pdfjs-dist (PDF text), fast-xml-parser (TCX), Playwright for a few end-to-end checks.

**Spec:** `docs/superpowers/specs/2026-11-07-shooting-analyzer-design.md`. Product truth: `PRODUCT.md`. Visual direction: Range Hall Lane Board (spec section 10). Sample files: `samples/`.

## Global Constraints

- UI language is Serbian; code, identifiers and commits are English.
- Only discipline is required to save a training; everything else is optional; saving an empty training needs an explicit confirmation.
- Disciplines are exactly: `air_rifle` (Vazdušna puška), `smallbore_3p` (MK puška trostav), `air_pistol` (Vazdušni pištolj), `smallbore_pistol` (MK pištolj). The number of shots is never part of a discipline.
- Default training name is `dd.mm. <discipline name>`; default date is today.
- All timestamps are stored as UTC; displayed in the user's time zone (default `Europe/Belgrade`). SCATT shot times are millisecond Unix epoch UTC; the SIUS CSV report time is local to the laptop.
- Alignment is always proposed and confirmed by the user; the app never silently matches. Match selection modes: last N, first N, from a chosen shot; no default mode.
- Within a confirmed match, SIUS shots map to SCATT shots one to one, contiguously, by order; individual shots can be marked ignored.
- Raw imported files are always stored unchanged (Supabase Storage, direct browser upload, 25 MB limit per file).
- Deletes are soft: a trash with a 30 day retention, plus an audit log of create, update and delete.
- Coach sees all of a linked shooter's trainings (results, training heart rate, original files). Fitbit and calendar derived data is hidden unless the shooter grants it for all trainings, selected trainings or a period. Either side can end a link at any time.
- Registration creates an inactive account; only the admin can activate it. The first admin is seeded.
- State is never conveyed by colour alone (solid, dashed, half-height, struck-through accompany colour). Orange flag = proposed/awaiting confirmation; black = confirmed.
- No credentials or tokens in chat or in the repository; secrets live in environment variables.

## Review Focus

1. Re-importing the same file into the same training must not create duplicates (hash check, user prompted). Pinned in Task 13.
2. A SIUS CSV in a different text encoding or with the mis-encoded group-size symbol must still parse. Pinned in Task 3.
3. Daylight-saving boundaries: a training around the 25 October clock change must keep shots ordered and heart-rate overlay aligned. Pinned in Task 7.
4. A coach whose link is ended (or never confirmed) must see zero rows, including raw files and storage objects. Pinned in Task 9.
5. A heart-rate file with gaps, zero samples or samples outside the training window must not crash the report; the overlay shows "nema pulsa". Pinned in Task 6.
6. A TCX file whose offset label is wrong (the real sample says `+03:00` for a Belgrade training in November): the user must be able to reinterpret the clock as a chosen zone before alignment. Pinned in Task 6.
